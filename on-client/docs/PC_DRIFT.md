# PC Drift: 판단 규칙과 한계 (마지막 총공세)

작성: S13ee · 작성일 2026-10-28 · 대상 소스: 이 문서가 들어 있는 커밋

**PC Drift — 내 PC, 평소와 달라진 것을 알려드립니다.**
평소와 달라진 것만 근거와 함께 할 일로 알려 주고, 확인한 일은 다시 귀찮게 하지 않는 개인 PC 점검 화면입니다.
방향과 설계 원칙은 `PRODUCT_DIRECTION.md`, 실행 방법은 `STUDENT_RUNBOOK.md` 10장에 있습니다.

표시 규칙은 `STUDENT_RUNBOOK.md`와 같습니다: [실행 확인] 이 PC에서 직접 본 것 · [코드 확인] 코드를 읽어 확인한 것 · [모의 확인] 실제 PC가 아닌 모의 입력(jsdom)으로만 확인한 것 · [UNV] 확인하지 못한 것.

## 1. 제공 기능과 직접 만든 부분

| 구분 | 내용 | 파일 |
|---|---|---|
| **제공** | 이 PC 값을 읽는 통로 `GET /api/pc/status`(CPU·메모리·디스크·네트워크·Windows 방화벽·Windows 기록) | `src/pc-status.mjs` (제공, 고치지 않음) |
| **제공** | 보호 현황의 「내 PC 상태」 카드와 「내 PC 확인」 버튼 | `public/pc-status-view.mjs` (제공) |
| **제공** | 꾸밈 파일을 읽어 앱 이름·색·카드 배치를 적용하는 기능 | `public/app.js`, `public/style.css` (제공) |
| **직접 만듦** | PC Drift 화면 전체: 점검 결과 판정, 점검 기록 저장, 평소 범위, 바뀐 것 찾기, 할 일·확인 처리·변화 기록, 견본 보기, 오류 안내 | `student/extension.mjs`의 `renderStatus` 위쪽 |
| **직접 만듦** | 앱 이름 `PC Drift`, 강조색, 학생 카드 먼저 배치, 학생이 준비한 아이콘(256×256 PNG). 첫 화면 그림은 넣지 않음 | `student/appearance.json`, `student/assets/brand-icon.png` |

- PC Drift는 제공 통로를 **「내 PC 점검」(또는 「다시 점검」)을 누를 때 한 번만** 부릅니다. 화면을 다시 그릴 때나 정해진 시간마다 스스로 부르지 않습니다. [코드 확인]
- 값을 재는 방법(CPU 200ms 표본 1회, Windows 기록은 최근 24시간 System·Application의 경고·오류를 최대 5,000건까지 집계 등)은 제공 기능이 정한 것입니다. [코드 확인: `src/pc-status.mjs`]
- 16단계 「보안 서버 연결 상태(기기·세션·알림·진단)」는 PC Drift 아래에 그대로 두었고, 보안 서버(SDP) 연결 여부와 PC 점검 결과를 섞지 않습니다. [실행 확인]

## 2. 한 번 점검할 때의 흐름

1. **점검**: 응답 형식(schema `aleph.on.pc-status.v1`, 출처 `local-pc`, 잰 시각)을 확인한 뒤 6개 항목을 따로 판정합니다. 응답이 왔다고 모든 항목을 실측으로 보지 않습니다. [코드 확인]
2. **저장**: 숫자와 켜짐/꺼짐만 이 브라우저에 저장합니다(최근 60회). [코드 확인]
3. **비교**: 바로 전 점검, 그리고 평소 범위(지난 점검 최근 20회, 5회 이상일 때)와 비교합니다. [코드 확인]
4. **할 일**: 3장 기준에 맞는 변화를 할 일로 등록합니다. [코드 확인] [모의 확인]
5. **확인 처리·해결**: 4장 규칙을 따릅니다. [코드 확인] [모의 확인]
6. **기록**: 발견·확인함·다시 할 일로·해결됨·참고를 시간순으로 남깁니다(최근 100건). [코드 확인]

화면 순서는 제공 설명서(`FINAL_PRODUCT_GUIDE.md` 10.4)의 "핵심 요약 → 다음 행동 → 상세 근거(펼치기)"를 따릅니다: 지금 할 일(요약) → 「다시 점검」·「견본 보기」(다음 행동) → 실측 요약 줄(실측 n/6·확인 불가 수·잰 시각·출처) → 「상세 근거 펼치기」(비교 결과와 6개 항목) → 「변화 기록 펼치기」. 확인 불가 수는 펼치기 밖 요약 줄에도 보입니다. [실행 확인]

## 3. "바뀜"으로 보는 기준과 이유

평소 범위는 이번 점검을 뺀 **지난 점검 최근 20회**로 만들고, **5회 미만이면 비교하지 않습니다.** 표본이 적을 때 비교하면 틀린 알림이 나오기 때문입니다.

| 항목 | 기준 | 종류 | 이유 |
|---|---|---|---|
| Windows 방화벽 | 프로필(Domain·Private·Public) 하나라도 켜짐 → 꺼짐 | 할 일 | 평소 값 없이도 바로 알릴 만한 변화. 다시 켜짐은 참고 |
| 디스크 여유 | 여유 10% 미만, 또는 평소 최저보다 5%p 넘게 감소 | 할 일 | 천천히 변하는 값이라 큰 폭일 때만. 10% 미만은 평소와 상관없이 위험 신호 |
| 메모리 | 평소 최고보다 10%p 넘게 높음 | 할 일 | 쓰는 앱에 따라 늘 오르내리므로 폭을 넉넉히 둠 |
| Windows 기록 | 최근 24시간 **오류** 수가 평소 최고보다 많음 | 할 일 | 경고는 평소에도 많고 흔해서 비교하지 않음 |
| 네트워크 | 인터페이스·IPv4 구성 개수가 바뀜 | 참고 | 와이파이·VPN 전환으로 자연스럽게 바뀜 |
| CPU | **3번 연속** 평소 최고보다 높음 | 참고 | 0.2초 순간 값이라 한 번 높은 것은 의미가 약함. 높아도 보안 문제라는 뜻은 아님 |
| 읽기 실패 | 이전엔 읽혔는데 이번엔 확인 불가 | 확인 필요 | 모르는 것을 정상으로 넘기지 않기 위해 |

- 60초가 지난 점검 결과는 "오래됨 · 현재 상태로 보지 않음"으로 표시합니다. [코드 확인]
- 오류 건수, 방화벽 켜짐, 네트워크 개수는 **침해 여부나 안전을 판정한 결과가 아닙니다.** 화면에도 그렇게 적습니다. [실행 확인]

## 4. 할 일 규칙

| 상황 | 처리 |
|---|---|
| 바뀐 것(할 일·확인 필요)을 찾음 | 할 일로 등록, 변화 기록에 "발견" |
| 상태가 그대로 | 「확인했음」을 누를 때까지 계속 보임. 같은 일을 두 번 등록하지 않음 |
| 「확인했음」을 누름 | 목록에서 빠지고 "확인함". 같은 상태가 이어지는 동안 다시 알리지 않음 |
| 실수로 누름 | 「다시 할 일로」로 되돌림 |
| 상태가 저절로 돌아옴 | 누르지 않아도 닫히고 "해결됨" |
| 돌아왔다가 다시 바뀜 | 새 할 일로 알림 |
| 평소 범위로 찾은 일(메모리·디스크 감소·오류 수) | **발견 당시의 기준값**을 기억해, 그 기준 안으로 돌아왔을 때만 해결로 봄 |
| 점검 실패, 그 항목을 못 읽음 | 할 일을 바꾸지 않음(해결로도, 새 할 일로도 보지 않음) |
| 시간이 지남 | 다시 알리지 않음 |
| 참고(네트워크·CPU·방화벽 다시 켜짐) | 할 일로 만들지 않고 변화 기록에만 남김 |

| 저장 위치 | 내용 |

- 비밀값·사용자 이름·IP 주소·Windows 기록 본문은 저장하지 않습니다. [코드 확인]

- 저장소를 쓸 수 없으면 "이번 실행 중에만 기억합니다"라고 표시하고, 평소 범위가 쌓이지 않습니다. [코드 확인] [모의 확인]

## 6. 견본 보기

- 할 일이 생겼을 때 화면 모양을 보여 주는 **고정 예시**입니다. 맨 위에 "견본 · 예시 화면 · 실제 이 PC의 값이 아닙니다"를 표시하고 모든 칸에 "예시"를 붙입니다. [코드 확인]
- 견본에서는 이 PC 값을 읽지 않고, 저장소·할 일·변화 기록을 읽거나 바꾸지 않으며, 「확인했음」은 눌리지 않습니다. [모의 확인]
- 방화벽을 일부러 끄는 등 설정을 바꿔 시험하지 않기 위해 만들었습니다.

## 7. 한계

| 한계 | 설명 |
|---|---|
| 기록은 이 브라우저·이 주소에만 | 브라우저 저장소라서 다른 브라우저, 다른 PC, 다른 포트(예: `:5190`)로 열면 기록이 따로 쌓입니다. 브라우저 데이터를 지우면 함께 지워집니다 |
| 처음 5회는 비교가 적음 | 평소 범위 비교는 지난 점검 5회부터입니다. 그 전에는 방화벽·네트워크·읽기 실패·디스크 10% 미만만 비교합니다 |
| 평소 범위는 단순한 최소~최대 | 통계적 이상 탐지가 아닙니다. 평소에 이미 나쁜 상태였다면 그것을 평소로 봅니다 |
| 방화벽이 처음부터 꺼져 있던 경우 | "켜짐 → 꺼짐" 변화만 알리므로, 첫 점검부터 꺼져 있으면 할 일로 만들지 않습니다(칸에는 꺼짐이 그대로 보임) |
| 측정 자체의 한계 | CPU는 0.2초 순간 값, Windows 기록은 건수만 셉니다. 백신 상태·열린 포트·업데이트 상태는 읽지 않습니다 |
| 설정을 바꾸지 않음 | 할 일은 확인 방법 안내까지이며, 고치는 것은 사람이 직접 합니다 |
| 실제 변화 화면 | 이 PC에서 실제로 할 일이 생긴 화면은 아직 보지 못했습니다. 할 일·해결 흐름은 모의 입력으로 확인했습니다 [UNV] |
| 자동 점검 파일 | 모의 입력 점검(jsdom)은 작성 도우미 환경에서 실행했고, 저장소에는 넣지 않았습니다(외부 의존성을 늘리지 않기 위해) |
| 처음 보는 사람 테스트 | 제공 설명서 10.1의 4번(처음 사용자에게 써 보게 하기)은 하지 않았습니다. 사용성은 작성자 본인과 키보드 검수로만 확인했습니다 |
| 접근성 검수 범위 | 키보드 조작만 확인했습니다. 200% 확대와 화면 낭독기(NVDA)는 확인하지 않았습니다 [UNV]. 제공 화면을 썼다는 이유로 접근성이 검증됐다고 보지 않습니다 |

3. 「견본 보기」에서 Space → 견본 화면
4. 「견본 닫기」에서 Enter → 원래 화면
5. 「상세 근거 펼치기」에서 Space → 펼쳐짐
6. 다시 Enter → 접힘
7. 「변화 기록 펼치기」에서 Enter → 펼쳐짐
